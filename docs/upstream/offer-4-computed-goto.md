**Title:** Offer: an implementation of `ring_vm_computedgoto()`, the function `vm.c` asks for

**Labels:** performance, enhancement

**Kind:** offer — a PR is ready if this is wanted

---

## Summary

`ring_vm_mainloop()` already dispatches to a computed-goto loop when
`RING_VM_COMPUTEDGOTO` is defined, `vm.h` declares the function, and the
comment says it still needs writing:

```c
#ifdef RING_VM_COMPUTEDGOTO
    if (pVM->nPC <= RING_VM_INSTRUCTIONSCOUNT) {
        /* The next function must be written if RING_VM_COMPUTEDGOTO is enabled */
        ring_vm_computedgoto(pVM);
    }
#else
```

We wrote it, and would be glad to contribute it if you want it.

## What it is

A mechanical transform of `ring_vm_execute()`'s switch:

- one label per opcode, **case bodies copied verbatim**;
- the label table in `codegen.h` enum order (opcodes that have no case
  in the switch fall through to the next check, exactly as the switch
  does);
- fetch, dispatch, and the stack-overflow check consolidated into one
  loop, so there is **no function call per instruction**.

It is generated by a script rather than written by hand, precisely so it
cannot drift from the switch. The script comes with the PR. The one
maintenance rule: rerun it if the opcode enum or a case body changes — a
stale label table would dispatch the wrong opcode.

Purely additive and guarded: without `-DRING_VM_COMPUTEDGOTO`, `vm.c`
compiles exactly as it does today.

## Measurements — stated honestly

Ours are from **WebAssembly**, which is the weakest possible case for
this technique: clang lowers both a dense switch and computed goto to
the same `br_table`, so the classic branch-prediction win largely
disappears. What is left is the loop consolidation.

| | measured |
|---|---|
| wasm, `-Os` | no measurable difference |
| wasm, VM core at `-O2` | **~9%** on dispatch-bound code (10,000-iteration loop), for +2.6 KB |

On **native x86/ARM**, where the distributed indirect jumps actually
interact with the branch predictor, this technique classically pays
considerably more — but we have not measured that, and would rather say
so than quote someone else's numbers. If there is interest, taking that
measurement on native Ring is the obvious next step, and we are happy to
do it.

## Correctness

Behavior is held identical to the fetch loop by running the whole
corpus through it: Ring's own `samples/` plus every runnable code block
in the documentation — roughly 850 programs — byte-exact against a
`ring.exe` built from the same source, with zero output differences.

Found and built while compiling the Ring 1.27 VM to WebAssembly. Say the
