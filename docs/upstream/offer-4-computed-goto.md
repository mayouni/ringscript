# TITLE: Offer: an implementation of ring_vm_computedgoto() — the function vm.c already declares and calls

<!-- ready to paste as a ring-lang/ring DISCUSSION or PR description -->

`vm.h` declares `ring_vm_computedgoto()` under `#ifdef
RING_VM_COMPUTEDGOTO`, `ring_vm_mainloop()` calls it, and the comment
there says *"The next function must be written if RING_VM_COMPUTEDGOTO
is enabled."* We wrote it, and this is an offer to contribute it.

## What it is

A mechanical transform of `ring_vm_execute()`'s switch into a
computed-goto dispatch loop: one label per opcode, case bodies
identical, label table in `codegen.h` enum order (the three opcodes
with no case — NewLabel, Package, NOOP — fall through, as the switch
does). Fetch, dispatch, and the stack-overflow check consolidate into
one loop with no function call per instruction.

It is **generated by a script** rather than written by hand, so it can
be regenerated whenever the opcode enum or a case body changes — the
script and its refusal guards (it will not write output if it captured
a suspicious number of case bodies) come with the offer:
https://github.com/mayouni/ringscript/blob/main/tools/regen-computedgoto.py

The generated function as currently shipped in RingScript:
https://github.com/mayouni/ringscript/blob/main/ringvm/src/vm.c
(the block at the end of the file, guarded by the same ifdef — without
`-DRING_VM_COMPUTEDGOTO` the file compiles exactly as stock).

## Honest measurements so far

All numbers are from **WebAssembly**, which is the pessimistic case
for this technique: wasm has no arbitrary goto, so clang lowers both a
dense switch and computed goto to the same `br_table`, and the only
available win is the loop consolidation.

- at `-Os`: no measurable difference
- with the VM core at `-O2`: a consistent **~9%** on dispatch-bound
  code (repeated A/B runs)

On **native x86/ARM**, where the per-opcode indirect jumps interact
with real branch prediction, computed-goto dispatch classically pays
considerably more than that — but that measurement has to be taken on
native Ring, and I did not want to claim numbers I have not taken.
If there is interest, I'll run the native A/B on the Ring benchmark
programs and include the results in the PR.

Correctness evidence: in RingScript this dispatch runs the full
conformance battery — ~850 programs (the official samples plus every
runnable documentation example) byte-identical to native ring.exe —
plus soak (40,000 evaluations) and fuzz (4,000 hostile inputs) suites.
