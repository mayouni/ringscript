Why this exists

RingScript did not start as a browser experiment. It arrived at the end of a long road that runs through a library, an engine, a framework — and, before any of them, through real applications built for people who had to use them every day.

The applications came first

Over the years I built business software where it actually gets used, not where it demos well: inside a bank, for a restaurant, and for a high school in Niger. Different worlds, the same lessons, learned the hard way.

A bank

Rules are the product. They change, they must be auditable, and "the system says so" is never an acceptable answer to a customer.

A restaurant

Speed and simplicity beat features. Staff turn over; whoever is at the counter tonight must be productive in ten minutes.

A high school in Niger

The connection drops, the power cuts, the browser is old. Software that assumes the cloud is always there is software that stops working.

The constraint that shaped everything: business software must keep working offline, stay understandable to the people who own the rules, and outlive the fashion of the season.

Softanza: a library, then an engine

Writing those systems in Ring made me want the language to say more with less. That became the Softanza Project — first a library that gives Ring a fluent, declarative way to work with strings, lists, data and rules; then an engine underneath it, so the same expressive code could stay fast and portable instead of paying for its elegance at runtime.

Softanza's premise is simple: code should read like the intention of the person who asked for it. When a banker describes a rule, the program should look like that sentence.

StzWeb: business applications that keep working

Libraries and engines still leave you facing the modern web stack. For the kind of applications above, that stack is a poor trade: a build pipeline to maintain, a dependency tree that rots, a framework that will be rewritten before the school year ends — and, at the end of it, an app that assumes a network.

So StzWeb was built the other way round: a framework for business applications that run offline, in the browser, on web standards that do not expire. Its core ideas come straight from the field:

Declare, don't code Entities, norms and flows are declared in a small closed grammar. The declaration is the specification, the documentation and the program at once.
Offline first The application runs in the browser and keeps its own durable, tamper-evident record. The network is an optimisation, not a prerequisite.
Visible over hidden Rejections, violations and refusals are shown, never silently swallowed. Trust is the product in a bank, and it is built from what the system is willing to show.
Calm over power Fewer moving parts, no build step, no framework churn — so a small team can still maintain the thing three years later.

The missing half: the language in the page

One gap remained. StzWeb could declare the business, store it and serve it — but the moment a page needed logic, we were back in JavaScript. Ring already speaks on the server, through Ring WebLib and the Bolt framework. The browser was the one place the language could not go.

RingScript closes that gap. Ring's own compiler and virtual machine, compiled to WebAssembly and kept resident in the page, so the same language writes the request handler and the click handler. For StzWeb it means a business rule can be evaluated by the JavaScript runtime and by Ring — side by side, from the same declaration, reaching the same verdict. For everyone else it means something simpler: you can script a web page in a calm language, with two files and no toolchain.

Where it stands

RingScript is version 0.9. It is complete in function and verified program-by-program against native Ring, and it already carries real work — the same four domains that started this story. It is not 1.0 yet because Softanza and StzWeb are themselves in progress, and a version number should be earned in production rather than announced.

If you build the kind of software that has to work in a school with no internet, in a restaurant at rush hour, or in a bank where every refusal must be explainable — this was built from that experience, and you are welcome to it.

— Mansour Ayouni, creator of the Softanza library for Ring
