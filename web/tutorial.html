Embedding Ring in a web page

Seven small steps from an empty HTML file to a page that runs Ring business logic with JSON in and out. Every "Run" button on this page executes against a single resident VM — the same instance from top to bottom, which is the whole point.

1. Load the runtime

Two files, no build step on the JS side: the loader (ringscript.js, a classic script — no bundler required) and the wasm module. Serve them over HTTP (zig build serve does exactly that) and initialize once:

<script src="ringscript.js"></script>
<script>
const ring = await RingScript.load("ringscript.wasm", {
    onOutput: text => console.log(text)   // VM stdout/stderr
});
</script>

That's a complete Ring 1.27 compiler and virtual machine, resident in your tab, in ~340 KB of wasm.

2. Evaluate code, read output

ring.eval(code) compiles and runs Ring source in the resident state and returns { ok, output, error }. Output is captured — see, ?, put, even C-level print() — in exact order:

see "Hello from Ring " + version() + nl
for i = 1 to 3 ? i next
→ output appears here

3. State persists between evals

This is what makes it a runtime rather than a calculator: globals, functions and classes survive from one eval to the next. Run these two in order:

aInventory = [ :apples = 12, :pears = 7 ]
func total aList
    n = 0
    for item in aList n += item[2] next
    return n
→ defines data + a function, prints nothing
? "items in stock: " + total(aInventory)
→ uses what the previous eval defined

4. Errors are trapped, never fatal

A compile error or runtime error returns ok: false with error carrying the real line number — and the VM (with all its state) survives. Run this, then re-run step 3's second demo to see the state intact:

? "before the storm"
thisFunctionDoesNotExist()
→ note the line number, and that partial output is kept

5. Interactive input — give

Pass an input queue as the second argument of eval; Ring's give consumes it line by line, echoing like a terminal. When the queue runs dry, the program gets a trappable error instead of hanging your page:

ring.eval('? "Name: " give n ? "Hello " + n', "Alice\n");
? "Enter two numbers:"
give a
give b
? "Sum: " + (0 + a + b)
→ runs with the input queue "15\n27"

6. Call Ring functions with JSON

ring.call(name, arg) is the runtime-mode door: your argument is serialized to JSON, decoded into a Ring pair-list ([ :key = value ]), and the function's return value travels back the same way, parsed and ready:

ring.eval('func Price aOrder return [ :total = aOrder[:qty] * aOrder[:unit] ]');
const r = ring.call("Price", { qty: 3, unit: 19.5 });
// r.result --> { total: 58.5 }
func Price aOrder return [ :total = aOrder[:qty] * aOrder[:unit] ]
→ defines Price, then calls it with { qty: 3, unit: 19.5 }

7. Ring calls back into JavaScript

Inside Ring, Platform(name, data) (or the lower-level jscall) reaches handlers you register with ring.on(name, fn); unhandled calls surface as DOM CustomEvents named ringscript:<name>. Handler return values travel back into Ring:

ring.on("notify", payload => {
    console.log("Ring says:", payload);
    return { ack: 1 };
});
aReply = Platform("notify", [ :msg = "hello page!", :n = 7 ])
? "JS acknowledged: " + aReply[:ack]
→ watch the reply make the round trip

8. Ship your own Ring library

There is no filesystem — on purpose. Pure-Ring libraries are baked into the wasm at build time: drop a .ring file into src/ringlib/, add one line to the embedded-file map in src/bridge.zig, rebuild. Ring's load then finds it exactly like a file:

// src/bridge.zig
.{ .name = "ringlib/mylib.ring", .data = @embedFile("ringlib/mylib.ring") },
load "ringlib/stzzql_smoke.ring"
→ runs an embedded 400-line library's test suite
