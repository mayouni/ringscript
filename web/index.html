The Ring language,
resident in your browser

RingScript compiles the Ring VM to WebAssembly and keeps it alive between evaluations — persistent state, trapped errors, interactive input, and a two-way JSON bridge to JavaScript. No plugins, no server round-trips, no Emscripten.

Open the Playground Read the Tutorial
Quick start — one command
zig build serve     # builds the wasm, serves this site
Requires Zig 0.15+. Then open http://localhost:8377/ — that's the whole workflow.

Resident, not batch

One RingState lives for the whole page. x = 5 in one eval, see x in the next. Errors are trapped with real line numbers and never kill the VM — 1000 evals, flat memory.

Native-exact

~850 programs — Ring's own samples, the documentation examples, and a 24-example gallery — produce output byte-identical to native ring.exe, verified continuously against the real thing.

Two-way JS bridge

ring.call("Fn", {…}) sends JSON in and gets JSON out; Ring's jscall() raises DOM events or invokes your handlers. Embed pure-Ring libraries straight into the wasm.

What it looks like

Ring — runs in the Playground exactly like this
new point { x=10 y=20 z=30 ? self }

class point x y z
Output — same bytes as native Ring
x: 10
y: 20
z: 30
JavaScript — the embedding API
const ring = await RingScript.load("ringscript.wasm");
ring.eval('func Double aData return [ :value = aData[:n] * 2 ]');
const r = ring.call("Double", { n: 21 });
// r.result --> { value: 42 }

Not a delivery vehicle — by design

RingScript is the interactive niche: playgrounds, notebooks, teaching, live business-rule evaluation. File systems, OS calls, threads and GUI bindings are deliberately absent — programs that ask for them get a clean, trappable Ring error, never a dead runtime.
